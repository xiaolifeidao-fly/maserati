# M6：运营化和恢复能力

目标：让系统可观测、可恢复、可排查。

## 范围

- DLQ
- 任务历史详情
- robot_run 看板
- robot_products 状态看板
- 当前锁和队列深度看板
- 客户端重启上报 `resumingLeases`
- 服务端对账
- 队列归档
- 手动重派
- 告警指标

## 验收标准

- 能看到每个 robot_run 当前状态、队列积压、正在执行任务。
- 能查看商品从 monitor 到 publish 的完整链路。
- 客户端崩溃重启后能恢复或停止本地残留任务。
- DLQ 任务能查看原因并手动重派。
- 锁泄漏、lease 超时、人工超时都有告警。

## 风险点

- 任务失败和运行实例失败要分开。
- 单个商品失败不能直接停止整个 robot_run。
- 环境级失败，如账号失效、代理不可用、profile 损坏，才需要标记 robot_run degraded / failed。

## 依赖

- M1-M5 的核心链路已跑通。
- 任务历史和运行态数据足够完整。

## 交付物

- DLQ 复盘页面。
- robot_run / robot_products 看板。
- 队列和锁观测面板。
- 客户端重启对账逻辑。
- 手动重派和告警能力。
